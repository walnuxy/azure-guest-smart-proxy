# 登录自启、守护和应用路径

2026-11-01 的一次目标机检查中，Mihomo 与本地端口正常，HTTPS 经显式代理成功，但桌面应用原先没有可用代理路径；启用指向本地入口的 Windows 当前用户系统代理后，默认代理请求与桌面连接均恢复。

同次检查发现目标机仍装旧版：没有 Supervise-GuestProxy.ps1 和 scripts/Lifecycle.ps1。虽然已有登录自启快捷方式，它没有 v3 异常恢复能力。生成或下载 v3 包不会自动升级既有电脑。

## 依次检查

1. 核对实际部署目录、脚本版本和当前用户的登录入口。Startup 是用户登录后触发，不等于未登录即可运行。入口存在也不等于已经经过重启验收。
2. 核对本包核心路径、PID 与创建时间、实际监听归属及本地 API；v3 还需核对 Supervisor 与心跳。
3. 核对 AUTO 实际选中出口，进行带证书校验的 HTTPS 测试。备用程序未运行时，没有可用备用。
4. 分别核对应用配置、Windows 当前用户系统代理与实际桌面进程连接。文件写对不证明已运行应用采用它；ChatGPT.exe 也可能属于 Codex，应看安装路径。
5. 目标机完成完整退出后重新启动与真实消息验收。HTTP 200、WebSocket 握手、CLI 成功都不能代替桌面生成。

## 系统代理

安装包默认不修改 Windows 系统代理。需要使用它时，先记录当前用户 Internet Settings 的 ProxyEnable、ProxyServer、ProxyOverride、PAC 等实际设置及类型，备份到本机，并明确它影响其他遵循系统代理的应用。

入口应从 state/deployment.json 的 MixedPort 读取，不能假定所有电脑都是 17890。设置前先验证该本地入口实际 HTTPS 可用；设置后验证 Windows 默认代理选择、HTTPS 和桌面进程连接。回滚恢复原值，不能覆盖后来发生的用户修改。

此处只记录排查方法和历史修复，不会在阅读或安装时自动修改网络。v3 核心恢复和系统代理是不同功能。重启验收需要用户完成，不应为此结束正在进行的桌面会话。
